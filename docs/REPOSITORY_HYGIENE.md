# HowRipe repository hygiene

This repository starts from the tracked tree of frozen production commit `6ada2f09bfb42d47449be223beb2cb77757a0528`, exported with `git archive`. The export contained 1,096 files. No prior Git history, local environment files, dependencies, build output, source masters, or newer deployment/live QA evidence was copied. The historical repository remains the development archive.

The production source, tests, routes, canonical origin, metadata implementation and all 43 runtime fruit images are unchanged. The public configuration example remains `NEXT_PUBLIC_SITE_URL=https://www.howripe.com`.

## Path classifications and publication changes

| Reference class | Treatment |
| --- | --- |
| Source-master archive paths | Repository-relative `source-assets/` references; masters remain local and excluded |
| Generated image provenance | Generic `<local-source-archive>/generated-images/` identifiers; originals are not shipped |
| Historical temporary worktrees | `<historical-worktree>` placeholder; branch and commit provenance retained |
| Image references inside an old worktree | Repository-relative `public/fruits/` paths |
| A temporary screenshot comparison baseline | `<local-baseline>` in retained audit text; obsolete executable probe removed |
| Machine-installed Playwright imports and Chrome executables | Archived scripts removed; maintained production smoke uses the installed `playwright` package and its Chromium |
| Development URLs in setup instructions and test fixtures | Retained intentionally; they are development examples or explicit origin-override tests |
| Loopback URLs in historical QA reports and captured local-page metadata | Retained as evidence of local runs, not as production URLs |
| Historical local preview links | Explicitly marked as requiring the recorded development server |
| File URLs and temporary system-cache paths | None present in the exported candidate |

The existing origin audit contains copied historical code snippets. Only machine-specific path portions were sanitized; its recorded local/preview URL classifications remain historical evidence.

On a fresh checkout, run `pnpm exec next typegen` before `pnpm exec tsc --noEmit`. Next.js generates the ignored `next-env.d.ts` and route types rather than exporting workstation-generated declarations.

Seven committed local HTTP-header captures use normalized LF endings with no blank EOF line. Header names and values are unchanged; this allows the initial commit to pass the whitespace gate.

## Generated QA evidence

Deployment metadata, live-browser screenshots/results, captured live-source headers/HTML/robots/sitemap, and redirect results are generated evidence. They are absent from the frozen export and narrowly ignored under `docs/qa/production-01/`. They can be regenerated by the deployment audit and browser smoke workflow; regeneration must be reviewed separately. Existing concise production QA documentation and the committed local QA evidence remain available.

## Maintained production browser smoke

`docs/qa/production-01/browser-check.mjs` resolves Playwright through the project's pinned dev dependency. It uses Playwright-managed Chromium and contains no workstation import or browser executable path.

Run from the repository root:

```sh
pnpm install --frozen-lockfile
pnpm exec playwright install chromium
node docs/qa/production-01/browser-check.mjs https://www.howripe.com
```

The script accepts an origin and an optional output directory. Its default output is the ignored `docs/qa/production-01/live-browser/` directory. It performs read-only page checks and does not deploy. Older iteration scripts targeted superseded UI stages, fixed development ports, browser selectors and one-off screenshot baselines. They are not maintained production tests. Their reports and screenshots are retained, and their executable sources remain available in the historical archive.
